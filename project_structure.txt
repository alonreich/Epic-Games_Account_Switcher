# EPIC GAMES ACCOUNT SWITCHER - ARCHITECTURAL GUIDE & PROJECT STRUCTURE

## 1) PROJECT OVERVIEW
Epic Games Account Switcher is a high-stability session manager for the Epic Games Launcher. It enables instant account switching without password or 2FA prompts by performing deep clones of authentication tokens, web cache, and registry identifiers.

## 2) MODULE BREAKDOWN

### A) Epic-Games_Account_Switcher-Client (WPF / MVVM)
Primary UI application orchestrating the session swaps.
- **AutoLoginService.cs**: A robust fail-safe/fallback mechanism. If the primary deep-clone session swap fails to bypass authentication, this service uses computer vision (OpenCV) and human-emulated input to automatically navigate the login UI and enter credentials. It acts as a "rescue" system to ensure the user is never locked out of their account.
- **MainViewModel.cs**: The brain of the UI.
  - **Optimized Monitor**: Background timer (5s) checks if `EpicGamesLauncher.exe` is running before performing heavy metadata detection.
  - **Zero-Click Capture**: Automatically terminates the launcher and all helper processes (`EpicWebHelper`, `EOSUserHelper`, etc.) during account capture to ensure no file locks.
  - **Unified Messaging**: Must ALWAYS use `CustomMessageBox` for consistency.
- **MainWindow.xaml.cs**: Handles high-performance drag-and-drop card reordering and UI animations (`AnimatedWrapPanel`).
- **App.xaml.cs**: Single-instance mutex logic with native window focus (`BringToFront`). Handles the smart-install/uninstall flow.

### B) Epic-Games_Account_Switcher-Globals (Shared Core)
- **AccountService.cs**: The Session Persistence Engine.
  - **Deep Capture**: Clones `LoginCache.json`, `PersistentAuthStorage.json`, AND `PersistentAuthStorage.bin`.
  - **Multi-WebCache**: Captures ALL `webcache*` directory variants into a unified `WebCaches/` storage folder.
  - **EOS Deep Clone**: Captures `Epic Online Services`, `EOSOverlay`, `EOSUserHelper`, and `EpicOnlineServicesUserHelper` from both `Local/Epic Games` and `Local/` root.
  - **Registry Engine**: Swaps critical identifiers like `AccountId`, `DeviceId`, and `EpicAccountId` via `RegistryData` dictionaries.
  - **Lazy Detection**: `GetDetectedMetadata` uses a lightweight cache. It only re-scans logs/INI files if the Registry `AccountId` has actually changed.
- **Globals.cs**:
  - **Bulletproof I/O**: `ForceDeleteDirectory` uses a 5-step retry loop with attribute resetting to overcome transient antivirus/system locks.
  - `RetryActionAsync`: Exponential backoff for all asynchronous file moves.
- **AppSettings.cs**: Stores the `RegistryKeysToSwap` list. Any new Epic login tokens found in the future must be added here.

### C) Support Tools
- **runas**: Small utility for elevated command execution.
- **SingleFilePacker**: Bundles the `Payload` folder into a single executable.
- **Installer**: C++ bootstrapper for runtime checks.

## 3) SESSION DATA MODEL
Stored in: `%LOCALAPPDATA%\Epic-Games_Account_Switcher\LoginCache\Epic_Games\`
- `accounts.json`: Metadata (Name, Email, RegistryData).
- `<AccountId>/`:
  - `LoginCache.json`, `Config/`, `Data/`, etc.
  - `WebCaches/`: Subfolders containing all captured `webcache*` variants.
  - `EOS_Data/`: Deep clones of all Epic Online Services directories.

## 4) STABILITY & UX MANDATES (FOR AGENTS)
1. **Never Prompt for Closure**: Use `EnsureEpicIsClosed` to terminate processes automatically.
2. **Handle All Cache Variants**: Epic frequently renames `webcache` folders (e.g., `webcache_4147`). Always iterate and capture all matches.
3. **Consistency**: Never use standard `MessageBox.Show`. Always use `CustomMessageBox`.
4. **I/O Safety**: Use `Globals.ForceDeleteDirectory` instead of standard `Directory.Delete` to prevent crash-on-lock.
5. **Registry Prefixes**: The registry engine uses type prefixes (`sz:`, `dw:`, `bin:`). Always strip or handle these when comparing raw IDs.

## 5) FLUENT UPGRADE PROCEDURE
When a newer version of the application is run on a system with an existing installation, it performs a 4-stage "Fluent Upgrade":
1. **BACKUP**: Current user data (accounts, settings, skins) is backed up to a temporary ZIP file.
2. **WIPE**: The old version is thoroughly uninstalled. All remnants (Program Files, Registry keys, logs, and temp files) are purged to ensure a clean state.
3. **INSTALL**: The new version is installed to Program Files, and shortcuts/registry protocols are re-registered.
4. **RESTORE**: The user's data is automatically restored from the temporary backup.

This ensures a seamless transition with zero data loss. If any stage fails, the user is notified with a detailed error dialog and a report is saved to `UpgradeError.txt`.
